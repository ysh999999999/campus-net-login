================================================================
重要：移动或整理文件夹后必须重新安装
================================================================
计划任务里记录的是 monitor.ps1 的绝对路径。文件夹一旦移动，
任务会指向失效路径，自动登录将静默停止。

    移动文件夹后，请右键「安装.bat」→ 以管理员身份运行。

可用「检查状态.bat」确认：若显示「计划任务仍指向旧路径」，即需重新安装。

常用操作
================================================================
1. 首次安装 / 重装：右键 安装.bat → 以管理员身份运行
2. 改账号密码：双击 设置账号密码.bat → 点【保存】即可，程序会自动重连一次
   （约 10 秒内生效；监控没在跑时保存会自动把它拉起来。原因见文末专章）
3. 查看是否正常：双击 检查状态.bat
4. 手动立即登录：双击 立即重连.bat
5. 临时不让自动登录（例如离校）：双击 暂停监控.bat，回来再 恢复监控.bat
6. 清理磁盘：双击 清理维护.bat，选 1（常规）

自动清理说明（v2.1 新增）
================================================================
监控每 24 小时自动执行一次清理，也可随时手动运行 清理维护.bat：

  · 归档：exe 把截图和 login_steps.log 写在 bin\（它的运行目录），
           清理时会自动搬到 shots\ 与 logs\
  · 截图：超过 7 天自动删除
  · 日志：超过 30 天自动删除（monitor.log 另有按大小轮转）
  · 残留：回收 %TEMP% 下本程序的 PyInstaller 解压目录（_MEI*）

保留策略可在 config\monitor_settings.json 的 cleanup 段调整：
    interval_hours          清理周期（默认 24）
    shots_keep_days         截图保留天数（默认 7，0=强制全删）
    logs_keep_days          日志保留天数（默认 30）
    temp_mei                是否回收解压残留（默认 true）
    temp_mei_max_age_hours  残留目录至少存在多少小时才清理（默认 6）

安全约定：
  · 只清理确认为本程序产物的目录（含 ddddocr 或 playwright 子目录）
  · 6 小时内的目录一律跳过，避免影响正在进行的登录
  · 遇到被占用的目录不会硬删，而是改名为 _MEI_delete_me_* 隔离，
    下次（或重启后）自动清掉

================================================================
常见问题
================================================================
Q：为什么 exe 和配置文件要放在一起？
A：exe 按自身所在目录查找 campus_net_config.json。把它移走会导致
   登录失效且无明显报错——这正是本项目以前踩过的坑。

Q：密码是明文存的吗？
A：是，保存在 bin\campus_net_config.json。请勿外传整个文件夹。

Q：清理会删掉我的截图吗？
A：只删 校园网\shots\ 下超过保留天数的登录过程截图，不碰其它任何位置。
   不放心可先运行 清理维护.bat 选 2（演练）看它会做什么。

Q：重装/回退怎么做？
A：_backup_20261001\ 里是改造前的原始文件，复制回根目录即可，
   但注意那时的脚本用的是平铺结构，需配合旧版计划任务路径。

Q：exe 坏了怎么办？
A：v2.1 已还原出 Python 源码（src\）。按 src\README.md 安装依赖后
   可直接 python campus_net_login.py 运行，或用 build.spec 重新打包。

行为说明
================================================================
· 每 5 分钟 ping 一次；网络异常时立刻尝试登录
· 网络正常且 HTTP 会话探测有效时，跳过无谓的重新登录
· 距上次登录超过 2 小时会强制保活一次
· 后台时段（默认 7:00-23:00）静默运行，不弹窗
· 连续失败会指数退避，5 次后进入 60 分钟冷却，避免冲击认证接口
· 失败时桌面换成 4K 主题壁纸并弹通知；网络恢复后【自动还原你原本的壁纸】
  （v2.8.0 起壁纸为 4K 高清主题图：主视觉「臣妾做不到啊」+ 右侧面板「连接失败」
   与检查清单，右下角标 DEV；按主屏比例放大到长边 3840，任何分辨率下都是高清。
   v2.9.0 起多张轮替：内置主题图 + assets\theme_*.jpg 网络素材依次挂出，
   游标记录在 config\wallpaper_rotation.txt；往 assets 里丢新的 theme_xx.jpg
   即自动加入轮替，删掉对应文件即跳过。
   v2.9.3 起，【自己找的壁纸】有两种版式，按文件名前缀自动区分，
   两种都是【整张原图、不裁边、不拉伸变形】：
     theme_full_xxx.jpg -> 整图居中大图（金框 + 投影，四周是主题渐变底）；
     theme_xxx.jpg      -> 装裱成白底金框卡片摆在左侧（原图像素摆放）。
   小图不做有损放大（卡片最多放大 1.25 倍、整图模式一律不放大），
   宁可小一点也保持清晰 —— 想铺得更满，换一张高分辨率的图即可。
   两种都随轮替自动上场：放进 assets 即生效，不必重启监控；
   卡片下方的说明文字自动取 assets\SOURCES.txt 里该文件名的条目，
   没写就显示「自定义素材 · 文件名」，不会再套用别人的剧照文案。
   预览见 docs\壁纸预览_1~5_*.jpg）
  （v2.1.1 起：先记下原始壁纸再改写，恢复时还原，不再把你原本的壁纸
   永久替换成绿色图）
· v2.4.0 起壁纸状态会【自愈】：只要网络恢复，红色壁纸就会被撤掉，
  不再依赖"下一次登录正好成功"才还原。三个时机都会检查：
    - 每个 ping 周期（网络正常即刻还原）
    - 暂停监控期间、免打扰时段内（静默还原，不弹通知）
    - 监控启动时：上次留下红屏而这次网络其实是通的，会等到网络就绪
      （最多 60 秒）后立刻还原
· 万一红色壁纸仍未自动褪去，双击 还原壁纸.bat 立即恢复

单实例与升级（v2.1.2）
================================================================
· 监控靠 config\monitor_heartbeat.json 判断"是不是已经有一个在跑"：
  存活实例每轮循环刷新 PID+时间戳，重复启动会安全退出而不是互相打架。
· 心跳超过 15 分钟没刷新（进程卡死/被强杀留下的死锁），下次启动会
  自动接管并尝试结束僵死实例，不会像以前那样永久卡在"已有实例运行"。
· 从 v2.1.1 及更早版本升级：旧实例没有心跳文件，而它通常是由计划任务
  以管理员权限启动的，普通窗口结束不了它。请右键 安装.bat → 以管理员
  身份运行一次，安装脚本会先停任务、再按心跳/命令行双通道结束旧实例，
  然后用新脚本重新启动。
· 复核：运行 检查状态.bat，"监控进程" 一栏会显示心跳是否正常。

免打扰时段（v2.3.0，可自定义）
================================================================
· 双击 设置免打扰.bat，菜单里可以直接改三件事：
    1. 修改免打扰时段      （默认 23:00-07:00，支持跨午夜、精确到分钟）
    2. 开启 / 关闭免打扰
    3. 修改后台静默时段    （就是默认 7:00-23:00 那个）
    4. 免打扰时是否完全停止自动登录
  改完会询问是否立即重启监控 —— 配置只在监控启动时读取，不重启不会生效。
· 免打扰时段内会发生什么：
    - 登录一律后台静默运行，绝不把窗口顶到前台
    - 不换红色失败壁纸、不弹系统通知
    - 若 skip_auto_login=true，则时段内完全不自动登录（最安静）
      若 =false（默认），仍会静默保活登录：既不吵你，也不会让你整夜断网
    - 立即重连.bat 手动触发的重连【不受免打扰限制】，随时可用
· 对应配置在 config\monitor_settings.json 的 quiet_hours 段：
      "quiet_hours": { "enabled": true, "start": "23:00", "end": "07:00",
                       "skip_auto_login": false, "mute_notify": true }
  想全天都静默，就把后台静默时段设成 00:00-23:59。

================================================================
磁盘占用：会不会越用越大？（v2.5.0 已封顶）
================================================================
· 结论：不会无限增长，稳态上限约 40 MB（不含程序本体 400 MB）。

| 产物           | 上限                                  | 机制 |
|----------------|---------------------------------------|------|
| monitor.log    | 2 MB × 4 份 = 8 MB                     | 超过 2 MB 轮转，保留 3 份副本 |
| login_steps.log| 1 MB                                   | 超过则只留末尾 400 行 |
| shots\ 截图    | 40 张（约 28 MB）                      | 超出删最旧的；另有 7 天过期 |
| bin\ 待归档    | 5 MB 左右                              | 每 24 小时移入 shots\ |
| TEMP 壁纸位图  | 约 6 MB                                | 每次清理周期删除 |

· 为什么之前会涨：login_steps.log 是每次登录往末尾**追加**的，修改时间永远是
  最新的，所以"保留 30 天"这条规则永远轮不到它 —— 它是唯一没有天花板的文件。
  截图同理：保活登录每 2 小时一次、每次留下几张，只按 7 天过期的话，
  7 天内可以堆到近 200 MB。v2.5.0 给这两项都加了硬上限。
· 想看当前占用：运行 检查状态.bat，会新增"产物占用"一栏。

开机宽限期（v2.4.0，专治"一开机就红屏"）
================================================================
· 现象：刚开机时网卡驱动、WLAN 关联、拨号都还没就绪，此时 ping 全部失败，
  监控误判为断网，立刻把桌面换成红色失败壁纸；等网络真正起来后，
  又因为"登录没被再次触发"而没人去把红屏撤掉。
· 现在监控启动后的前 150 秒属于【宽限期】：
    - 网络不通 → 不切红色壁纸、不弹失败通知、不累积失败次数、不进冷却
    - 改为每 20 秒重试一次登录，网络一通就正常接管
    - 宽限期结束后仍不通 → 恢复原有行为（切红壁纸 + 退避/冷却）
· 启动时若发现上次遗留的红色壁纸，会给网络最多 60 秒的就绪时间，
  一旦通了立即还原，不会把昨天的红屏带进今天。
· 对应配置在 config\monitor_settings.json 的 startup 段：
      "startup": { "grace_sec": 150, "retry_interval_sec": 20 }
  把 grace_sec 改成 0 可关闭该功能（网络不通立即切红壁纸）。
· 生效方式：脚本和配置只在监控启动时读取。请重启一次电脑，或右键
  安装.bat → 以管理员身份运行一次，v2.4.0 的壁纸自愈与宽限期才会接管。
  生效后运行 检查状态.bat 应能看到"开机宽限期: 150s"这一行。

================================================================
登录程序改版（v2.2.0）：不再往 TEMP 解压
================================================================
· 原来的 exe 是 PyInstaller **单文件（onefile）** 打包：每次启动都要把
  187 MB 解压到 `%TEMP%\_MEI*`（实测占用 274～387 MB），单次登录常超过 3 分钟，
  进程被挂起时残留不会清理——此前累积出的约 1 GB 垃圾就是这么来的。
· 现在改成本地重建的 **onedir** 版：exe（7.5 MB）+ `_internal\`（约 400 MB）
  放在 `bin\` 下**就地加载**，不再产生任何 TEMP 解压，冷启动显著变快。
  `%TEMP%` 实测从 891 MB 降到 24 MB。
· 注意：`CampusNetLogin.exe` 与 `_internal\` 必须在一起，**只拷贝 exe 会无法启动**。
  旧的单文件 exe 保留在 `_backup_20261002_onefile\CampusNetLogin_onefile.exe`，
  需要回滚时把它放回 `bin\` 即可（记得删掉 `_internal\`）。
· 想自己重新打包（例如 Edge 大版本更新后）：
      cd src
      pyinstaller build.spec

改完密码要等多久才生效（v2.9.4 起：点保存即可，自动重连）
================================================================
· 现在（v2.9.4 及以后）：
  双击 设置账号密码.bat 改好账号密码 → 点【保存】→ 程序会自动重连一次，
  通常 10 秒内就用新密码重试（若当时监控没在运行，保存时会自动把它拉起来）。
  → 不需要重装，也不需要重启电脑。
· 为什么以前要等很久（v2.9.3 及以前）：
  监控在连续登录失败后会进入【指数退避 / 冷却】——
  第 1~4 次失败之后分别等 5 / 10 / 20 / 30 分钟再试；
  第 5 次起进入【冷却 60 分钟】，此后固定每 60 分钟才试一次。
  这段计时状态保存在监控进程的内存里，改配置文件不会打断它，
  所以最坏要等满 60 分钟才用新密码重试，看起来像“没反应”。
  （登录程序 exe 每次启动都会重新读配置，所以“新密码没被读到”这种事不存在。）
· 老版本的手动解法（v2.9.3 及以前）：改完密码后，再双击一次 立即重连.bat。
  它立刻用新密码试一次，【不受退避 / 冷却 / 暂停 / 免打扰限制】，通常 10 秒内响应
  （若此刻正有一次登录在跑，会在它结束后立即处理）。
· 判断是否已生效：打开 logs\monitor.log，看到下面几行即说明已按新密码重试——
      MANUAL: 收到立即重连请求
      MANUAL: 重试节奏归零（此前连续失败 N 次）      ← 之前失败过才会有
      LOGIN: 启动 CampusNetLogin.exe (mode=...)
· 完整机制与时间表见 docs\技术说明与已知限制.md 第 2 节。
