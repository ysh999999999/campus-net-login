- **适用范围**：校园网自动登录守护（X-file / 校园网）v2.9.6
- **最后更新**：2026-10-08
- **阅读提示**：本文讲的是「机制」和「已知问题」。日常怎么用请看《使用说明.txt》。
  文中路径均相对于程序根目录。

## 1. 配置读取机制（理解后面所有问题的前提）

### 1.1 两个配置文件，彼此独立

| 文件 | 谁读 | 内容 |
|---|---|---|
| `bin\campus_net_config.json` | **只有 `CampusNetLogin.exe`** | 账号、密码、登录地址、运营商、重试次数、登录后等待秒数 |
| `config\monitor_settings.json` | **只有 `monitor.ps1`（监控）** | ping 目标、会话探测、退避与冷却、免打扰、清理、日志上限 |

`monitor.ps1` 全文**没有任何一处读取 `account` / `password`**——监控既不知道也不关心你的账号密码，
它只负责"发现断网 → 启动 `CampusNetLogin.exe --auto` → 看结果"。

### 1.2 账号密码在什么时刻被读取

`src\campus_net_login.py` 第 147~165 行是**模块级代码**（不是函数）：

```python
if getattr(sys, 'frozen', False):
    BASE_DIR = os.path.dirname(sys.executable)      # 冻结后 = exe 所在目录
config_path = os.path.join(BASE_DIR, 'campus_net_config.json')

with open(config_path, 'r', encoding='utf-8') as f:
    config = json.load(f)

ACCOUNT  = config['campus_network']['account']
PASSWORD = config['campus_network']['password']
```

这段代码在**进程启动时执行一次**，之后全程不再重读。

好消息是：监控每次登录都是 `Start-Process CampusNetLogin.exe --auto` 拉起一个**全新进程**
（`monitor.ps1` 第 1388 行），所以**每一次登录尝试都必然读到磁盘上最新的配置**。

> **结论：不存在"监控缓存了旧密码"这回事。** 改密码后不生效，原因不在"谁读了什么"，
> 而在"监控什么时候才会去发起下一次尝试"。

### 1.3 重试状态是存在内存里的

监控把两个关键状态放在**内存变量**里：

| 变量 | 含义 |
|---|---|
| `$script:failStreak` | 连续失败次数 |
| `$nextLoginAt` | 下一次最早可重试的时刻 |

它们**不受配置文件影响**，只由运行结果驱动，且**进程一重启就全部归零**。
第 2 节的问题就是它们造成的。

## 2. 问题 #1：改完密码不会立刻生效（★ v2.9.4 已修复）

### 2.1 现象

> 装好之后密码填错了 → 一直登录失败 → 把密码改成正确的 → **程序长时间不重试**，
> 看起来"不响应"；必须重新安装（`安装.bat`）或重启电脑才恢复。

### 2.2 核查结论

**该问题真实存在，只要密码错误就会稳定复现；已在 v2.9.4 修复（见 2.6）。**

不是因为配置没写进去，也不是因为监控缓存了旧密码，而是：
**此刻监控正处于「指数退避 / 冷却」期，在 `$nextLoginAt` 到达之前，它不会发起任何新的登录尝试。**

### 2.3 根因

`scripts\monitor.ps1` 主循环：

```powershell
$script:failStreak++
if ($script:failStreak -ge $coolThreshold) {                 # 默认 5
    $delay = $cooldownMinutes * 60                           # 默认 60 分钟
} else {
    $delay = [Math]::Min($backoffBase * [Math]::Pow(2, $script:failStreak - 1), $backoffMax)
}
$nextLoginAt = (Get-Date).AddSeconds($delay)
```

`config\monitor_settings.json` → `retry` 段的实际生效值：

| 配置项 | 默认值 | 含义 |
|---|---|---|
| `consecutive_failures_before_cooldown` | 5 | 连续失败几次后进入冷却 |
| `cooldown_minutes` | 60 | 冷却时长（分钟） |
| `backoff_base_sec` | 300 | 退避基数（秒），按 2 的幂增长 |
| `backoff_max_sec` | 1800 | 单次退避上限（秒），30 分钟 |
| `after_login_wait_sec` | 120 | 每次尝试后固定等待（秒） |
| `ping.interval_sec` | 300 | 网络检测周期（秒） |

### 2.4 时间表：密码错误时到底会发生什么

令 **T = 第一次登录失败的时刻**：

| 第 N 次失败 | 发生时刻（相对 T） | 之后要等多久才会再试 |
|---|---|---|
| 1 | 0 | 300 秒（5 分） |
| 2 | +5 分 | 600 秒（10 分） |
| 3 | +15 分 | 1200 秒（20 分） |
| 4 | +35 分 | 1800 秒（30 分） |
| 5 | +65 分 | **3600 秒（冷却 60 分钟）** |
| 6 及以后 | 每次再 +60 分 | 3600 秒（固定 60 分钟） |

也就是说：**从第一次失败算起约 65 分钟之后，重试节奏就固定成了每小时一次。**
于是"改完密码要等很久"的**最坏情况是整整 60 分钟**。再叠加：

- 主循环**每 300 秒**才检查一次网络（`ping.interval_sec`）；
- 每次登录尝试本身要跑几分钟（`exe.wait_ms` 上限 180 秒，加上 exe 自身内部重试）。

### 2.5 为什么"重新安装 / 重启"就好了

`安装.bat` 会重新注册计划任务并重启 `monitor.ps1` 进程 → `$script:failStreak` 归零、
`$nextLoginAt` 重置为 `MinValue` → 立刻恢复检测与登录。注销/重启电脑同理（进程被重建）。

> 但**根本不需要这么重**。见 2.6 / 2.8。

### 2.6 v2.9.4 的修复（已实施）

两处改动，让「保存即生效」真正成立。

**改动 1 —— `scripts\set_account.ps1`**：新增函数 `Invoke-ImmediateReconnect`，
保存成功后（原子替换之后）自动写重连标志；顺带在监控没运行时把它拉起来。

```powershell
# 保存成功后自动执行
Set-Content -Path (Join-Path $rootDir "config\reconnect.flag") `
            -Value (Get-Date -Format "yyyy-MM-dd HH:mm:ss") -Encoding UTF8
```

同时界面文案一起纠正（见 2.9）：窗口改为「保存后会自动重连一次，无需重装 / 重启电脑。」，
弹窗改为「账号密码已保存，程序已按新密码重新尝试登录。」+ 实际结果说明。

**改动 2 —— `scripts\monitor.ps1`** 手动重连分支里把退避状态一并归零：

```powershell
if (Test-Path $reconnectFile) {
    Remove-Item $reconnectFile -Force -ErrorAction SilentlyContinue
    Log "MANUAL: 收到立即重连请求" "INFO"
    if ($script:failStreak -ne 0) {
        Log ("MANUAL: 重试节奏归零（此前连续失败 " + $script:failStreak + " 次）") "INFO"
    }
    $script:failStreak = 0                  # ← v2.9.4 新增
    $nextLoginAt = [datetime]::MinValue     # ← v2.9.4 新增
    InvokeLogin
    ...
}
```

> **为什么两处都必须改**：只做改动 1，标志文件确实会被立刻消费、立刻登录一次；
> 但如果这一次也失败（例如校园网侧还没同步好新密码），`failStreak` 会**接着旧计数继续累加**，
> 下一次重试依旧要等满 60 分钟——问题只解决了一半。
> 改动 2 把计数归零，等价于「重新开始」。手动重连本来就是"人明确要求现在就用最新配置试一次"，
> 这个语义也更符合直觉。

**改动 3 —— `scripts\reconnect.ps1`**（`立即重连.bat` 的实际执行体）：**先无条件写标志，再判定监控状态**。

旧写法是「先判定监控在不在跑，**只有在跑才写**标志」：

```powershell
$procs = @(Get-CimInstance Win32_Process -Filter "Name='powershell.exe'" |
           Where-Object { $_.CommandLine -like "*monitor.ps1*" })
if ($procs.Count -ge 1) { Set-Content $flag ... }   # 判定在跑 → 写标志
else { Start-Process monitor.ps1 }                  # 判定没跑 → 拉起监控（不写标志）
```

`Win32_Process.CommandLine` 对**权限高于当前进程**的目标读不到：计划任务若以「最高权限」运行，
普通用户双击 `立即重连.bat` 就永远读到空，于是被误判成“未运行”——既不写标志，
又去启动一个会被单实例锁立刻挡回的新进程，表现出来就是「点了没反应」。

v2.9.4 改为三步：① **先无条件写标志**（请求绝不丢失，这是唯一凭据）；
② 用**心跳文件时间戳**（`config\monitor_heartbeat.json`，不受权限影响）判活，进程表仅作兜底；
③ 判定“未运行”时照样拉起监控——即使它其实在跑，新实例也会被单实例锁挡回，无害。

> 实测：写标志 → 监控消费 → 日志出现 `MANUAL: 收到立即重连请求`，全程 **3 秒**。

**风险评估（实施前评估）**：很低。即使监控当时没在运行，写下的标志文件也会在监控下次启动时被消费，
不产生残留副作用。

### 2.7 升级到 v2.9.4 之后怎么用

1. 双击 `设置账号密码.bat`，填好账号密码 → **点保存**
2. 弹窗会给出结果，两种情况都不用你额外操作：
   - 「已通知监控，约 10 秒内会用新密码重试一次」→ 等它跑完即可
   - 「监控此前未在运行，已自动启动」→ 等它跑起来即可
3. 想确认，打开 `logs\monitor.log`，应看到：
   - `MANUAL: 收到立即重连请求`
   - （此前失败过才会有）`MANUAL: 重试节奏归零（此前连续失败 N 次）`
   - `LOGIN: 启动 CampusNetLogin.exe (mode=...)`
4. 若此刻正有一次登录在执行（`InvokeLogin` 最长约 3 分钟），本次请求会在它结束后立即处理。
5. `立即重连.bat` 仍然保留，作用不变，随时可手动触发。

### 2.8 老版本（≤ v2.9.3）的手动规避方式

**改完密码后，再双击一次 `立即重连.bat`。**

这个分支位于**退避/冷却判断之前**，所以它**完全不受退避与冷却限制**。
`reconnect.ps1` 只负责写标志文件；监控的等待是分片的，每 10 秒检查一次标志
（`Sleep-WithFlags`），因此通常 10 秒内就会响应。

> 补充：`立即重连.bat` 在「暂停监控」和「免打扰」时段**同样有效**，随时可用。

### 2.9 一处界面文案已随之修正

旧版窗口写着「保存后立即生效，无需重新安装。」，保存成功的弹窗写「已保存，下次运行自动生效。」——
严格说都不算错（**下一次登录**确实会用到新密码），但容易让人误以为"保存完就会马上自动重试一轮"，
在退避/冷却期会落空。v2.9.4 起文案已按 2.6 改写。

## 3. 问题 #2：网络恢复后壁纸仍停在失败提示图（★ v2.9.5 已补齐残余缺口）

### 3.1 现象

断网 → 桌面被换成红色「连接失败」提示图 → 网络其实早就恢复了，红屏却一直挂着，
直到下一次（甚至下下次）断网才被顺带换掉。

### 3.2 核查结论：确实发生过，日志里有完整的正反两面证据

`logs\monitor.log` 未轮转（从 09/26 至今完整），每次切换失败壁纸都能对上还原记录：

| 切换失败壁纸 | 是否自动还原 | 耗时 |
|---|---|---|
| 09/28 14:58 | ✅ 15:21 切回【已恢复】壁纸 | 23 分 |
| **10/01 13:05** | ❌ **无任何还原记录** | **一直挂着** |
| 10/03 09:26 | ✅ 09:37 已还原为原始壁纸 | 11 分 |
| 10/08 12:11 | ✅ 12:19 已还原为原始壁纸 | 8 分 |
| 10/15 20:47 | ✅ 20:56 已还原为原始壁纸 | 9 分 |

10/01 那次就是本问题：13:12 起日志一直在打 `OK: 网络正常`（网络早已恢复），
却没有任何还原动作，红屏一直挂到 10/03 09:37 才被下一轮还原带走，中间约 **44 小时**。
当时运行的是 v2.0.0 之前的旧版（10/02 00:13 起日志才有 `[INFO]` 级别标签）。

### 3.3 根因

旧版只在「登录成功」这一条路径上还原壁纸。网络自己恢复、或冷却/探测跳过了登录时，
没有任何代码去撤掉红屏——`monitor.ps1` 源码里至今留着这句自述：

> 以前只在"登录成功"这条路径上还原，于是网络自己恢复、或冷却/探测跳过登录时，红屏会一直挂在桌面上。

### 3.4 修复（分两层）

**第一层（v2.4.0 起）——把还原点铺满所有分支。** `Sync-FailWallpaper` 检查
「是否仍留有失败标记」，只要还留着，网络一恢复就立刻还原：

| 位置 | 覆盖场景 |
|---|---|
| 登录流程内 | 登录成功且网络已通（不受后台时段限制，夜里也能撤） |
| 主循环·网络正常 | 巡检发现网络通 → 立刻还原，不等下次登录 |
| 主循环·暂停期间 | 「暂停监控」时网络恢复照样撤 |
| 主循环·免打扰 | 免打扰时段网络恢复 → 静默撤掉，不弹通知 |
| 启动自检 | 上次遗留的红屏，这次开机网络通就还原（最多等 60 秒等网卡就绪） |
| `还原壁纸.bat` | 手动兜底 |

**第二层（★ v2.9.5）——补掉「还原失败却照样清标记」的残余缺口。**

`SetOkWallpaper` 以前是无条件清标记：

```powershell
Restore-OriginalWallpaper | Out-Null   # 返回值被丢弃
Clear-FailState                        # 不管有没有还原成功，标记一律清掉
```

于是万一「还原」这一步本身失败（原始壁纸文件被删、恢复提示图生成或应用失败），
标记照样被清掉，**之后所有自愈点都认为"没有失败态"**，红屏永久留在桌面且再也不会重试。

v2.9.5 起：

1. `ApplyWallpaper` 不再无条件返回成功——Win32 分支校验 `SystemParametersInfo` 的返回值，
   注册表分支回读比对；设置没生效就是 `$false`。
2. `Restore-OriginalWallpaper` 明确返回值语义：`$true` = 桌面已确认回到正常状态
   （已成功还原 / 本来就不是本程序改的、无需处理），`$false` = 确实需要还原却没做成。
3. `SetOkWallpaper` **只在拿到 `$true` 时才清标记**；失败则保留两个状态文件，
   记一条 `WALLPAPER: 还原动作未成功（第 N 次）`，**60 秒后重试**
   （`Sync-FailWallpaper` 同样尊重这个冷却期，避免每个循环点重复刷同一行日志）；
   反复失败时日志会明确提示可双击 `还原壁纸.bat` 手动处理。

### 3.5 验证

- **单元级**：用测试替身替换掉「真的去改桌面」的那几个函数，模拟
  「原始壁纸应用失败」「恢复提示图生成失败」「冷却期内重复调用」「当前壁纸并非本程序设置」
  等 7 组场景、共 **22 项断言全部通过**，全程不触碰真实桌面。
- **端到端**：在真实监控上伪造一次失败态（`wallpaper_orig.txt` 指向**当前正在使用的壁纸**，
  因此画面不会有任何变化），触发还原后日志输出
  `WALLPAPER: 已还原为原始壁纸 -> D:\清嘉\动态壁纸\未标题-1_画板 1 副本 3.png`，
  两个状态文件被正确清除。这同时证明 `SystemParametersInfo` 在本机确实返回非 0，
  新判定不会误伤正常路径。

## 4. 问题 #3：把 Windows 系统主题缓存当成原始壁纸（★ v2.9.6 已修复）

> **触发条件**：桌面背景是 **幻灯片放映 / Windows 聚焦 / 部分动态壁纸**。
> 默认的「图片」模式不会触发（本机就是图片模式，所以一直没露头）。

### 4.1 现象

- 断网后桌面换成红色「连接失败」壁纸（正常行为）；
- 网络**已经恢复**，红屏却**一直不消失**；
- 最迷惑的是 `logs\monitor.log` 里明明白白写着
  `WALLPAPER: 已还原为原始壁纸 -> ...`——**桌面却没有任何变化，日志在说谎**。

### 4.2 根因：记录的"原始壁纸"和红图，其实是同一个文件

Windows 在使用幻灯片 / 聚焦壁纸时，注册表

```
HKCU\Control Panel\Desktop\Wallpaper
```

的值**不是用户挑的那张图**，而是 Windows 自己的转码缓存：

```
%APPDATA%\Microsoft\Windows\Themes\TranscodedWallpaper
```

而任何一次 `SystemParametersInfo(SPI_SETDESKWALLPAPER)` 都会让 Windows
**重新生成这个缓存文件**——包括我们自己切红屏那一下。

完整因果链：

```
桌面是幻灯片壁纸 → 注册表 Wallpaper = ...\Themes\TranscodedWallpaper
        |
        v
Save-OriginalWallpaper 把它当成"用户的原始壁纸"记进 config\wallpaper_orig.txt
        |
        v
切红屏 → Windows 把红图转码【覆盖写入同一个缓存文件】
        |
        v
网络恢复 → Restore-OriginalWallpaper 按记录去还原
        |   该文件此刻的内容就是红图 → 桌面当然还是红屏
        v
ApplyWallpaper 的 SPI 调用本身是成功的 → 返回 true → 日志报"已还原"
        |
        v
Clear-FailState 清掉失败标记 → 之后所有自愈点都认为"没有失败态"
        |
        v
红屏永久留下，且再也不会重试
```

### 4.3 为什么 v2.9.5 挡不住

v2.9.5 修的是「SPI 调用失败却谎报成功」（校验 `SystemParametersInfo` 返回值）。
而本问题里 SPI 调用**是真的成功了**——它确实把那张图设上去了，
只不过那张图的内容早就被换成了红图。两者根因不同，必须单独加守卫。

### 4.4 本机有没有中招（2026-10-16 核查）

| 检查项 | 实测值 | 结论 |
|---|---|---|
| 注册表 `Wallpaper` | `D:\清嘉\动态壁纸\未标题-1_画板 1 副本 3.png` | 真实图片路径，**不是**缓存 |
| 背景类型 `BackgroundType` | `0`（图片） | 不是幻灯片 |
| `Themes` 目录 | 仅 `TranscodedWallpaper` + `slideshow.ini`（0 字节） | 无 `Transcoded_000/001` |
| `TranscodedImageCache` 解出 | 同上那张 PNG | 兜底来源也没命中缓存 |
| 日志中 `Transcoded` 出现次数 | **0** | 从未把缓存当成原图 |
| 日志中 `已记录原始壁纸` | 10/08、10/15，路径均为真实 PNG | 记录正确 |

**结论：本机没有中招，但代码里确实没有这层防护——属于"只差一个触发条件"的潜伏缺陷。**

顺带确认了机制属实：`TranscodedWallpaper` 的修改时间是 `2026/10/15 20:56:25`，
与日志里 `已还原为原始壁纸` 的时间**完全同秒**，
说明每调用一次 SPI，这个缓存文件就被重写一次。

### 4.5 修复（v2.9.6，两层）

**第 1 层 · 守卫（先把"卡死"堵死）**

新增 `Test-SystemWallCache`：凡命中
`...\Microsoft\Windows\Themes\TranscodedWallpaper`、`Transcoded_*`，
或**整个 `%APPDATA%\...\Windows\Themes\` 目录**（该目录里全是 Windows 自己生成/管理的
缓存文件，没有一张是用户挑的图）的路径，一律**不作为"原始壁纸"**：

| 位置 | 作用 |
|---|---|
| `Get-WallpaperFromCache` | 兜底来源也不返回缓存路径 |
| `Save-OriginalWallpaper` | 不记录缓存路径 |
| `Restore-OriginalWallpaper` | 旧版本已写进记录的缓存路径，读出来直接放弃 |
| `restore_wallpaper.ps1` | 手动还原工具同样识别，并提示"到 个性化→背景 重选一次" |

**第 2 层 · 内容备份（让你那张图真的回来）**

只做第 1 层的话，用户最后只能看到绿色「已恢复」提示图，原来那张壁纸回不来。
所以还要：在**切红屏之前**（此刻缓存内容仍是用户那张图），把缓存文件的**内容**复制到
`config\wallpaper_backup.<png|jpg|bmp>`（后缀按文件头嗅探，认不出的格式就不备份），
并把**备份路径**记进 `wallpaper_orig.txt`；还原时应用这个备份，画面就回到用户原来那张图。

还原成功后还多做一步：把备份内容**写回原来的系统缓存文件**，并让桌面重新指向它
（`Restore-BackupToCache`）。否则注册表指向的备份文件一旦被正常清理，
重启后桌面会变成默认壁纸。备份的来源路径记在 `config\wallpaper_backup.src`。

> 若备份失败（缓存格式认不出、读写错误等），自动退回第 1 层行为，只保证"不卡死"，
> 不会留下半截状态。
