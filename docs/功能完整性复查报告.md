## 四、本轮新增修复（v2.1.2）：心跳式单实例

**根因**：旧实现用"扫描 powershell 进程命令行里有没有 monitor.ps1"来区分「真重复启动」和「上次异常退出留下的死锁」。但计划任务以 Highest（管理员）权限启动的进程，其命令行对普通窗口**读不到**，于是既有"误判为僵死→接管"，也有"旧实例永远挡住新版"两种相反故障。

**修复**：

1. `monitor.ps1`
   - 新增心跳文件 `config\monitor_heartbeat.json`（PID + 时间戳 + 版本）；
   - 主循环每轮、Sleep-WithFlags 每 60s、登录等待期间每 30s 刷新一次；
   - 抢不到互斥锁时按「心跳 → 命令行扫描 → 兜底接管」判定：心跳新鲜且进程存活才退出；心跳停滞 >15 分钟则判定僵死，自动结束并接管；无心跳（2.1.1 及更早的旧版）时回落到命令行扫描。
2. `install.ps1`：先 `Stop-ScheduledTask`（否则 `MultipleInstances=IgnoreNew` 会让启动被忽略），再按「心跳 PID + 命令行」双通道结束旧实例，删除陈旧心跳后重启。
3. `status.ps1`：新增心跳显示（正常 / 停滞 / PID 不存在 / 无心跳=旧版）。
4. 文档中补充「单实例与升级」章节。

**实测中的真实故障**：PID 5344 是 01:06 启动的 v2.1.0 旧实例（由计划任务以 Highest 启动），一直独占互斥锁，普通窗口 `Stop-Process` / `taskkill` 均 Access denied，导致 v2.1.1 反复打印"已有另一个监控实例在运行，本次退出"。已通过 `Stop-ScheduledTask` 结束它，v2.1.2 实例（PID 9316）已接管并正常运行。

## 六之二、壁纸状态自愈与开机宽限期（v2.4.0）

用户反馈的现象：**开机时校园网没连上 → 桌面变红；之后网络恢复了，红屏却一直挂着没人撤。**

根因（两个真缺陷，都在代码里确认过）：

1. **还原只挂在"登录成功"这一条路径上。** `InvokeLogin` 成功后才 `SetOkWallpaper`。于是这些情况下红屏不会被撤——网络是自己恢复的（没走登录）、正在冷却/退避、会话探测判定"会话有效"而跳过登录。主循环里 `$netOK` 为真时只记了一行日志，什么都没做。
2. **开机瞬间就误判断网。** 刚开机时网卡、WLAN 关联、拨号都没就绪，ping 全失败 → 立刻切红壁纸。而失败又会累积 `failStreak`，5 次后进入 60 分钟冷却，反而让网络迟迟起不来。

另外发现两个隐患：`Save-OriginalWallpaper` 用 `Set-Content -Encoding UTF8` 写入，会带 BOM，读取时路径比对与 `Test-Path` 都会失败 → 恢复时只能退回绿色提示图；免打扰时段只记状态不换壁纸，却没记录原始壁纸，恢复时同样会退成绿色图。

修复：

- **壁纸状态自愈 `Sync-FailWallpaper`**：只要还留着失败标记，就在每个 ping 周期检查网络，一恢复立刻还原。接入点覆盖了全部循环分支——网络正常分支（已知网络通，零开销）、暂停期间、免打扰时段（静默还原，不弹通知）。
- **启动自检改为等待网络就绪**：上次留下红屏而这次网络其实是通的，最多等 60 秒（每 10 秒探一次），一通就还原，不再把昨天的红屏带进今天。
- **开机宽限期 `startup.grace_sec = 150`**：启动后 150 秒内网络不通，不切红壁纸、不弹通知、不累积失败次数、不进冷却，改为每 20 秒重试登录；宽限期结束仍不通才恢复正常流程。
- **失败状态文件改为两行**：第二行记录本程序实际应用的红图路径。恢复时若拿不到原始壁纸记录，只有确认"当前桌面确实是我们自己那张红图"才用提示图顶掉，否则不动——避免把用户自己换的壁纸覆盖掉。
- **原始壁纸记录补了兜底**：`TranscodedImageCache` 作为第二来源（开机早期 `Wallpaper` 值常为空），写入改为 UTF-8 无 BOM，读取时剥离 BOM。`还原壁纸.bat` 同步支持。

验证：10 个 ps1 静态检查（括号配对 / 函数重名 / BOM）全绿；`monitor_settings.json` 无 BOM、可解析、`startup` 段已生效。运行时验证需重启监控后观察日志中的 `INIT: 开机宽限期 150s` 与 `WALLPAPER: 网络已恢复但仍留有失败标记 -> 立即还原壁纸`。

## 六之三、磁盘占用封顶与恢复初始状态（v2.5.0）

用户提问："这个时间长了，日志和其他产生的垃圾会很多吗？" —— 会，而且已经找到了两个没有天花板的地方。

**`logs\login_steps.log` 没有任何上限。** 它每次登录往末尾追加，mtime 永远是最新，而 `logs_keep_days` 是按 mtime 判断的，所以"保留 30 天"这条规则永远轮不到它。这是全项目唯一一个会无限增长的文件。

**截图只按天数过期不够。** 保活登录每 2 小时一次、每次留下 3～4 张 png（每张 0.5～0.8 MB），只靠 7 天过期的话，7 天内可以堆到近 200 MB。

修复：

- `login_steps_max_bytes = 1 MB` / `login_steps_keep_lines = 400`：超过就只留末尾 400 行。`monitor.ps1` 的 `Invoke-Retention` 与 `cleanup.ps1` 都加了这段。
- `shots_max_files = 40`：超出删最旧的，与 7 天过期双保险。
- 稳态上限：monitor.log 2 MB × 4 份 = 8 MB（原有轮转）、步骤日志 1 MB、截图约 28 MB、bin 待归档约 5 MB → **合计约 40 MB**，不再增长。
- `检查状态.bat` 新增"产物占用"一栏，直接看当前 logs / shots 的 MB 与张数、以及是否触碰上限。

新增 `scripts\reset.ps1` + `恢复初始状态.bat`（自提权），三档：

1. **恢复初始未安装状态**（推荐）：停监控 → 移除计划任务 → 还原壁纸 → 清空日志/截图/运行状态/TEMP 残留。保留程序本体、账号、监控设置、源码、文档。之后需重新 `安装.bat` 才会开机自启。
2. **只清垃圾不卸载**：监控照常跑，只清产物。
3. **彻底重置**：在 1 的基础上连 `campus_net_config.json`（账号）与 `monitor_settings.json` 一起删，等同于刚解压，需二次输入 DELETE 确认。

`_backup_*` 旧备份目录（其中单文件版 exe 约 187 MB）不会被自动删，脚本会列出大小单独询问。

顺带清理：本次会话在 `Documents\Agent\...\build\dist` 留下的 409 MB 构建副本已删除（`bin\_internal` 里已有完整可运行副本）。

## 六之七、账号密码保存失败修复（v2.9.1）

**现象**：双击 `设置账号密码.bat`，点「保存」弹错：

```
保存失败: Exception calling "Replace" with "3" argument(s):
          "The path is not of a legal form."
```

**根因**（PowerShell 与 .NET 互操作的经典陷阱）：

写配置的三步里，最后一步用了

```powershell
[System.IO.File]::Replace($tmpPath, $configPath, $null)   # 第三个参数是"备份文件路径"
```

PowerShell 把 `$null` 绑定到 .NET 的 `string` 参数时，会**先转成空字符串 `""`**（而不是真正的 null），
于是 `File.Replace` 内部对空路径调 `Path.GetFullPath("")`，
抛 `ArgumentException: The path is not of a legal form.`。

只要目标配置文件存在，这一步必然失败 —— 所以密码**从来没有保存成功过**
（`bin\campus_net_config.json` 的时间戳一直停在安装当天，正是佐证）。

**修复**：既然脚本本来就要做 `.bak` 备份，直接把真实备份路径传进去，由 `Replace` 自己完成备份：

```powershell
if (Test-Path $configPath) {
    [System.IO.File]::Replace($tmpPath, $configPath, $backupPath)   # 原子替换 + 备份
} else {
    [System.IO.File]::Move($tmpPath, $configPath)                   # 首次生成配置，无需备份
}
```

顺带把 `catch` 的错误本地化补了一条路径异常兜底。
